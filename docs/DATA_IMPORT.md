# Импорт данных

Как официальные данные haval.ru попадают в каталог приложения, что происходит
при ошибке и как проверить результат без доступа к сети.

## 1. Источники

Основной источник — **https://haval.ru/purchase/catalogues/** : на странице
опубликованы каталоги и прайс-листы в PDF (`cdn.perxis.ru/originals/<id>/original`).
Вторичные — `haval.ru/`, `haval.ru/models/`, `haval.ru/online-stock/`.

Реестр всех документов: `src/data/haval/source-documents.json` (28 записей).
У каждой записи — тип (`price-list` / `catalogue` / `page`), модель, ссылка,
дата публикации, контрольная сумма, статус разбора и число извлечённых цен.

Подробный разбор по документам — в [DATA_SOURCES.md](./DATA_SOURCES.md).

## 2. Пайплайн `scripts/catalog.mjs`

```
npm run catalog            # то же, что full
npm run catalog:discover   # найти документы на странице каталогов
npm run catalog:import     # скачать PDF → извлечь текст → разобрать цены
npm run catalog:validate   # проверить полноту и целостность результата
npm run catalog:diff       # сравнить результат импорта с текущим каталогом
npm run catalog:report     # отчёт об изменениях (+ --apply → журнал)
npm run catalog:full       # discover → import → validate → diff → report
```

Полезные флаги: `--model=m6` (только одна модель), `--apply` (записать
журнал изменений), `--update-registry` (обновить реестр документов).

Результат каждого запуска — `reports/catalog-run-<команда>-<timestamp>.json`
и `reports/catalog-run-latest.json`. Каталог `reports/` **не коммитится**
(см. `.gitignore`): это артефакты, а не данные приложения.

### Принцип безопасного обновления

1. импорт пишет результат во временный набор (`reports/`);
2. проверяются обязательные поля;
3. результат сравнивается с текущим каталогом;
4. формируется список изменений;
5. подтверждённые цены каталога **не перезаписываются автоматически** —
   решение принимает человек;
6. история проверок дополняется;
7. результат фиксируется в отчёте.

Следствия, реализованные в коде:

- **неудачный запуск не затирает результат предыдущего успешного импорта**
  (иначе следующая команда `diff` осталась бы без точки сравнения);
- **пустой результат импорта помечается явно**: diff не выдаёт «0 изменений»
  за подтверждённое отсутствие изменений, а пишет
  «сравнение не выполнено»;
- **документ, который не удалось разобрать**, получает статус
  `needs-manual-review` и попадает в отчёт, но не влияет на цены.

## 3. Разбор прайс-листа

`scripts/lib/parse-price-list.mjs`:

1. PDF → текст (`scripts/lib/pdf-text.mjs`, библиотека `unpdf`);
2. текст → строки; markdown-подобные таблицы разбираются на ячейки (`toCells`);
3. денежные значения ищутся по формату (`moneyValues`): пробелы-разделители,
   диапазон правдоподобия `MIN_PLAUSIBLE_PRICE`…`MAX_PLAUSIBLE_PRICE`.
   Технические числа (масса, клиренс, объём) не принимаются за цены;
4. строки цен объединяются в логические группы (`buildMoneyGroups`): метка
   («МЦП руб») и значения стоят в документе на разных строках;
5. названия комплектаций ищутся после заголовка `КОМПЛЕКТАЦИЯ`
   (`buildNameGroups`);
6. если таблица цен повторяется в документе, выбирается наиболее полный
   экземпляр (об этом пишется предупреждение);
7. дата начала действия ищется в тексте («Предложение актуально с 14.08.2026»)
   и переводится в ISO (`isoFromRuDate`);
8. результат проходит `validateParsed`.

### Что считается неуспешным разбором

`validateParsed` возвращает `ok: false`, если:

- не извлечено ни одной записи;
- есть дубликаты комплектаций;
- цена вне диапазона правдоподобия.

Предупреждение (не ошибка) — неполный результат относительно ожидаемого числа
позиций. Такой результат **не применяется**.

## 4. Сопоставление с каталогом

`scripts/lib/diff.mjs`:

- `trimSignature(name)` разбирает название на уровень оснащения, коробку,
  привод, топливо, двигатель и мощность. Название из документа
  («ОПТИМУМ, МТ 143 Л.С.») и из каталога («Оптимум, 1.5T MT 143») дают
  совместимые подписи;
- `matchTrim(row, trims)` ищет совпадение: сначала точное по нормализованному
  названию, затем по подписи, затем уточняет по модельному году;
- если подходящих вариантов несколько (например, бензин и дизель с одинаковым
  названием), функция возвращает `null` — **угадывать запрещено**. Такая
  запись попадает в `diff.ambiguous`.

`diffPrices` возвращает пять списков: `unchanged`, `changed`, `added`,
`missing`, `ambiguous`.

## 5. Проверка без доступа к сети

Текст двух официальных прайс-листов сохранён в репозитории:

- `tests/fixtures/price-list-m6.txt`
- `tests/fixtures/price-list-jolion.txt`

```bash
node scripts/verify-parsed-documents.mjs
```

Скрипт прогоняет **тот же** разбор и **то же** сравнение, что и сетевой
импорт, и отвечает: совпадают ли цены приложения с официальными документами.

Успех — это не только отсутствие ошибок разбора: список `changed`, `added`,
`missing` и `ambiguous` обязан быть пустым, а `unchanged` — непустым.
Текущий результат: **8 цен совпали, расхождений нет** (M6: 2 позиции,
JOLION: 6 позиций).

Эта проверка запускается и в CI — она не требует доступа к haval.ru.

## 6. Ручной импорт

Если автоматический сбор невозможен (источник ограничивает доступ), значения
переносятся из документа в JSON по схеме `price-lists/README.md`:

```bash
npm run import:price-list -- price-lists/<файл>.json
```

Правила: `sourceUrl` и `priceUpdatedAt` обязательны, модель — только из
каталога, цена — положительное число строго из документа, дубликаты
отклоняются. При любой ошибке импорт отклоняется **целиком**.

Другие команды:

```bash
npm run verify:sources                      # доступность источников + сверка тизеров
npm run verify:sources -- --record          # + запись в историю проверок
npm run update:prices -- --dry-run          # сбор тизеров без записи
npm run seed:price-history                  # стартовая точка истории цен
```

## 7. Что делать при выходе нового прайс-листа

1. `npm run catalog:full` — получить расхождения.
2. Открыть `reports/catalog-changes.md` и `reports/catalog-diff.json`.
3. Сверить каждое изменение с PDF-документом вручную.
4. Внести изменения в `src/data/haval/` (`trims.ts`, `specs.ts`,
   `equipment.ts`, `offers.ts`) и обновить `meta.ts`.
5. `npm run catalog:report --apply` — дополнить журнал изменений
   (`catalog-changes.json`) и историю цен (`price-changes.json`).
6. `npm run seo` (sitemap) и `npm run check` (типы, линтер, тесты, smoke, сборка).
7. Обновить `docs/DATA_SOURCES.md`.
