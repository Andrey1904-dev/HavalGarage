# Кредитная математика

Все формулы реализованы в `src/utils/loan.ts` и `src/utils/credit.ts` и покрыты
тестами `tests/unit.test.ts`, `tests/calculators.test.ts`.

## 1. Обозначения

| Символ | Смысл |
| --- | --- |
| `S` | сумма кредита (principal) |
| `P` | ежемесячный платёж |
| `r` | месячная ставка = годовая / 12 / 100 |
| `n` | срок в месяцах |

## 2. Аннуитетный платёж

```
P = S · r · (1 + r)^n / ((1 + r)^n − 1)
```

При `r = 0` — вырожденный случай: `P = S / n`.

```ts
annuityPayment(S, annualPercent, n)
```

Возвращает `NaN`, если `S ≤ 0` или `n ≤ 0` — это сигнал «расчёт невозможен»,
а не ноль.

## 3. Обратные задачи

| Задача | Формула | Функция |
| --- | --- | --- |
| Срок по платежу | `n = ln(P / (P − S·r)) / ln(1 + r)` | `termFromPayment(S, rate, P)` |
| Сумма кредита по платежу | `S = P · ((1 + r)^n − 1) / (r · (1 + r)^n)` | `principalFromPayment(P, rate, n)` |
| Ставка по платежу | аналитического решения нет — бисекция по `r` (платёж монотонно растёт по `r`), 100 итераций | `rateFromPayment(S, P, n)` |

`termFromPayment` возвращает `NaN`, если `P ≤ S·r`: такой платёж не покрывает
даже проценты, кредит не гасится никогда. Это честный отказ, а не «∞ месяцев».

`rateFromPayment` возвращает `0`, если платежи не покрывают даже тело долга.

## 4. Остаток долга

```
B(k) = S·(1 + r)^k − P·((1 + r)^k − 1) / r
```

`remainingBalance(S, rate, n, paidMonths, payment?)` — используется в графике и
в расчёте досрочного погашения.

## 5. График платежей

`buildSchedule(...)` (`src/utils/credit.ts`) строит помесячный график аннуитета:

- проценты месяца = остаток долга на начало месяца × `r`;
- часть в тело долга = платеж − проценты;
- остаток уменьшается на часть в тело долга;
- последний платёж корректируется, чтобы остаток стал ровно 0.

`aggregateByYear(...)` сворачивает график в годовые итоги для диаграммы.

## 6. Досрочное погашение

`simulatePrepayment({ ..., mode: 'term' | 'payment' })`:

- `term` — платёж прежний, срок сокращается;
- `payment` — срок прежний, платёж уменьшается.

Экономия считается как разность сумм выплат по исходному и новому графикам,
без «оценочных» коэффициентов.

## 7. ПДН (долговая нагрузка)

`pdnRelief(...)` считает, какую часть официально подтверждённого дохода
занимает платёж, и какой доход нужен, чтобы уложиться в порог. Значение
используется как ориентир: методика конкретного банка может отличаться, что
прямо указано в интерфейсе.

## 8. Правила округления

1. **Промежуточные значения не округляются.** Ставка, степени, логарифмы
   считаются в двойной точности.
2. **Деньги округляются только при выводе** — функциями `src/utils/format.ts`
   (`fmtMoney`, проценты).
3. Сравнения в тестах выполняются по неокруглённым значениям; округление
   проверяется отдельно.

## 9. Чего расчёт НЕ делает

- не обещает, что результат совпадёт с графиком конкретного банка: даты
  платежей, комиссии, страховки и правила округления банка неизвестны;
- не является офертой или публичным предложением;
- не подбирает ставку «по рынку»: ставка либо из официальной программы,
  либо введена пользователем и подписана как **«Расчётное предположение»**;
- не округляет платёж «в пользу банка».

## 10. Подбор по бюджету

`searchByBudget(...)` (`src/utils/budget.ts`):

1. из максимального платежа вычитается эксплуатационный бюджет (если задан) —
   `availableForLoanPayment`;
2. по аннуитетной формуле считается максимальная сумма кредита —
   `principalFromPayment`;
3. к ней прибавляется первоначальный взнос → максимальная цена автомобиля;
4. из каталога берутся комплектации с подтверждённой ценой, у каждой считается
   платёж, переплата и признак `withinBudget`;
5. обязательные ограничения (тип кузова, привод, наличие функций) —
   **жёсткие**: не прошедшие их варианты попадают в отдельный список с
   указанием причины, а не «протискиваются» в выдачу;
6. если ничего не подходит, результат объясняет почему и показывает расчётные
   рычаги: увеличить срок (`termFromPayment`), увеличить взнос или снизить
   цену автомобиля.
