# Архитектура HavalGarage

Документ описывает **реальное** состояние кода на 2026-10-10. Если раздел
расходится с репозиторием — актуален репозиторий; сообщите об этом в issue.

## 1. Общая схема

```
                    ┌────────────────────────────────────────────────┐
  haval.ru          │  Пайплайн импорта (Node, scripts/)            │
  ┌──────────────┐  │  catalog:discover → :import → :validate →     │
  │ каталоги,    │──▶  :diff → :report                              │
  │ прайс-листы  │  │  результат: reports/ (в git не коммитится)    │
  └──────────────┘  └───────────────────┬────────────────────────────┘
                                        │ проверил человек → применяет вручную
                                        ▼
                        src/data/haval/*.ts  (типизированный снимок каталога)
                                        │
                                        ▼
  Браузер ──── React-приложение (SPA) ──── расчёты (src/utils/*) ──── localStorage
                                        │
                                        └── (опционально) Supabase: заявки на кредит
```

Приложение — **чистый фронтенд**: сборка Vite, публикация на GitHub Pages.
Своего backend нет и не требуется: все данные каталога вшиты в бандл как
типизированные модули, все расчёты выполняются в браузере.

## 2. Стек

| Слой | Технология | Почему |
| --- | --- | --- |
| Сборка | Vite 7 (`vite.config.ts`) | быстрый dev-server, code splitting через `React.lazy` |
| UI | React 19 + TypeScript 5.9 (`strict`, `noUncheckedIndexedAccess`) | типы как защита от путаницы в ценах и ставках |
| Стили | Tailwind CSS 4 (`@tailwindcss/vite`) + дизайн-токены в `src/index.css` | тёмная тема, единая типографика |
| Роутинг | react-router-dom 7, `BrowserRouter` с `basename` | GitHub Pages отдаёт приложение по подпути `/HavalGarage/` |
| Графики | chart.js 4 + react-chartjs-2 | история цен, график платежей |
| Иконки | локальный набор `src/components/icons.tsx` + `lucide-react` (частично) | никаких внешних CDN |
| PDF | pdfmake 0.3 (ленивый импорт) | кириллица через `vfs_fonts`, отдельный chunk |
| Экспорт | собственные `src/utils/export.ts`, `export-data.ts` | печать, PDF, CSV, JSON |
| Тесты | встроенный `node:test` + esbuild-сборка наборов | без тяжёлых раннеров |
| Опциональная БД | `@supabase/supabase-js` (только заявки на кредит) | работает и без ключей: приложение деградирует, а не падает |

Node 22 (см. `.github/workflows/*`), пакетный менеджер — npm (`package-lock.json`).

## 4. Маршруты

| Путь | Страница | Назначение |
| --- | --- | --- |
| `/` | `HomePage` | обзор, быстрые сценарии |
| `/catalog` | `CatalogPage` | модели по официальному модельному ряду |
| `/trims` | `TrimsPage` | все комплектации с фильтрами (привод, мощность, коробка, цена, платёж) |
| `/advisor` | `AdvisorPage` | детерминированный помощник по выбору |
| `/models/:slug` | `ModelPage` | комплектации, характеристики, оснащение, программы, история цен |
| `/compare` | `ComparePage` | сравнение 2–3 комплектаций, состояние — в URL |
| `/calculator` | `CalculatorPage` | кредитный калькулятор, обратные задачи, ПДН, досрочное погашение |
| `/budget` | `BudgetPage` | подбор по максимальному платежу с обязательными ограничениями |
| `/ownership` | `OwnershipPage` | стоимость владения (TCO) |
| `/plan` | `PlanPage` | план накопления |
| `/favorites` | `FavoritesPage` | избранное и сохранённые расчёты |
| `/programs` | `ProgramsPage` | кредитные программы и спецпредложения |
| `/stock` | `StockPage` | автомобили в наличии (подтверждённые вручную позиции) |

попадают в основной chunk.

### 5.2 Ключевое правило: цена — это запись, а не число

Цена всегда хранится как `PriceRecord` (см. `types.ts`) и обязательно имеет
`priceType`:

`msrp` · `confirmed-discount` · `credit-program` · `trade-in` · `specific-car` · `historical` (плюс `teaser`, `stock`, `with-benefit` в данных предложений).

Разные типы **никогда не складываются и не усредняются**. Подробности — в
[PRICING_RULES.md](./PRICING_RULES.md).

### 5.3 Состояние

- React-контексты (`src/context/`): сценарий калькулятора, избранное и
  сохранённые расчёты, список сравнения.
- Персистентность — `localStorage` через `src/utils/storage.ts` (версионированные
  ключи `haval-garage.*.v1`, миграции, защита от приватного режима).
- Состояние сравнения и фильтров комплектаций дополнительно дублируется в
  **URL** (`/compare?trims=…`, `/trims?drive=…`), чтобы ссылкой можно было
  поделиться и чтобы она переживала перезагрузку.

## 6. Слой расчётов

Всё в `src/utils/` — чистые функции без React, покрытые тестами.

| Модуль | Отвечает за |
| --- | --- |
| `loan.ts` | аннуитет, обратные задачи (срок, сумма, ставка), остаток долга, досрочное погашение, ПДН |
| `credit.ts` | сценарий покупки: эффективная цена, взнос, платёж, график, переплата |
| `budget.ts` | подбор по максимальному платежу, обязательные ограничения, сортировка |
| `required-down.ts` | обратный расчёт: какой нужен взнос (или срок) под заданный платёж |
| `tco.ts` | стоимость владения, разделение «официальные данные / пользовательские / нет данных» |

| `tradein.ts` | сценарии трейд-ин vs самостоятельная продажа |
| `advisor.ts` | детерминированный помощник (правила + подтверждённые данные) |
| `export.ts`, `pdf-export.ts`, `export-data.ts` | печать, PDF, CSV, JSON |
| `format.ts`, `date.ts` | деньги, проценты, даты |

Математика — в [CREDIT_MATH.md](./CREDIT_MATH.md).

## 7. Почему помощник (`/advisor`) — не языковая модель

Языковая модель потребовала бы ключа API. В статическом приложении на GitHub
Pages ключ неизбежно попадает в открытый бандл, поэтому:

1. ключ хранить негде → внешняя модель не подключена;
2. имитировать «умный» ответ случайными формулировками — значит создавать
   ложную уверенность, что прямо запрещено требованиями к проекту.

Помощник детерминирован: `detectIntent` определяет тип вопроса, дальше ответ
собирается из подтверждённых данных каталога, а деньги считают те же функции,
что и калькуляторы. Если данных нет, он отвечает «нет подтверждённых данных».

**Как подключить модель, если появится безопасный backend** (не сделано, только
план): собственный serverless-провайдер держит ключ на сервере, фронтенд
отправляет вопрос и *уже собранный* контекст каталога, модель отвечает только
переформулированием готовых фактов. До появления такого провайдера
`src/utils/advisor.ts` остаётся единственным источником ответов.

## 8. GitHub Pages: ограничения и как они учтены

| Ограничение | Решение |
| --- | --- |
| Статика по подпути `/HavalGarage/` | `base` в `vite.config.ts` задаётся только для build; все ссылки — относительные |
| Нет server-side rendering | `scripts/smoke.mjs` рендерит все маршруты в jsdom и ловит ошибки гидратации/эффектов |
| Прямой переход на `/models/h9` даёт 404 | `public/404.html` — копия `index.html` (SPA-fallback) |
| Нет серверных секретов | БД подключается publishable-ключом с RLS; секретный ключ запрещён guard-шагом CI |
| Размер бандла | `React.lazy` + отдельные chunk'и pdfmake и графиков; CI проверяет сумму JS ≤ 3 MiB |
| Кэширование | Vite добавляет хэши в имена файлов |

## 9. Пайплайн импорта

Подробно — в [DATA_IMPORT.md](./DATA_IMPORT.md). Коротко:

```
npm run catalog:discover   найти документы на haval.ru/purchase/catalogues/
npm run catalog:import     скачать PDF, извлечь текст, разобрать цены
npm run catalog:validate   проверить полноту и целостность
npm run catalog:diff       сравнить с текущим каталогом
npm run catalog:report     отчёт об изменениях (+ журнал с флагом --apply)
```

Импорт **никогда не перезаписывает** `src/data/haval/trims.ts автоматически:
решение о применении цен принимает человек по официальному прайс-листу.

## 10. Что где проверяется

| Проверка | Команда | Что гарантирует |
| --- | --- | --- |
| Типы | `npm run typecheck` | `tsc -b --noEmit` по всему проекту, включая тесты |
| Линтер | `npm run lint` | eslint 10 (типы, хуки, react-refresh) |
| Тесты | `npm test` | 191 проверка: кредитная математика, каталог, импорт, помощник |
| Smoke | `npm run smoke` | все маршруты рендерятся без ошибок (jsdom) |
| Сверка с документами | `node scripts/verify-parsed-documents.mjs` | цены каталога совпадают с сохранённым текстом официальных прайс-листов |
| SEO | `npm run seo` | `sitemap.xml` и `robots.txt` соответствуют каталогу (CI падает, если sitemap устарел) |
| Сборка | `npm run build` | прод-бандл |

Полный прогон: `npm run check`.
