# Правила работы с ценами

Документ описывает, как в проекте хранятся и показываются цены. Правила
реализованы в коде (`src/data/haval/types.ts`, `src/data/haval/prices.ts`,
`src/utils/budget.ts`, `src/components/PriceMeta.tsx`) и покрыты тестами.

## 1. Цена — это запись, а не число

```ts
type PriceType =
  | 'msrp'          // МЦП из официального прайс-листа
  | 'with-benefit'  // цена с подтверждённой выгодой (условия — в Offer)
  | 'trade-in'      // цена при сдаче автомобиля в трейд-ин
  | 'credit'        // цена при оформлении кредитной программы
  | 'stock'         // цена конкретного автомобиля в наличии
  | 'teaser'        // цена из тизера без раскрытой комплектации
```

Каждая запись `PriceRecord` несёт: значение, тип, дату, с которой цена
действует (`validFrom`), дату проверки (`verifiedAt`) и ссылку на
первоисточник (`sourceUrl`).

**Запрещено:**

- складывать выгоды разных типов («МЦП − трейд-ин − кредитная программа»);
- усреднять цены разных типов;
- показывать цену без указания типа;
- подставлять цену одного типа там, где пользователь ждёт другой.

В интерфейсе тип виден: рядом с суммой выводится `PriceMeta` (тип, дата
начала действия, признак устаревания, ссылка на источник).

## 2. Что считается подтверждённой ценой

Подтверждённой считается цена, которая:

1. содержится в официальном прайс-листе haval.ru (PDF с
   `cdn.perxis.ru/originals/...`), **и**
2. сопоставлена с конкретной комплектацией (не «модель вообще»), **и**
3. имеет дату, с которой действует (`priceValidFrom`), **и**
4. имеет ссылку на документ-первоисточник.

Сейчас подтверждённых цен — **47** (все типа `msrp`), по 14 официальным
прайс-листам. Остальные 24 записи в `prices.ts` — это цены с выгодой,
трейд-ин, позиции в наличии и тизер; они **не** считаются МЦП и не
участвуют в подборе по бюджету по умолчанию.

## 3. Устаревание

- `PRICE_STALE_AFTER_DAYS` задаёт возраст, после которого цена помечается как
  требующая проверки. Цена при этом **не скрывается и не удаляется** —
  показывается с явной пометкой.
- `priceFreshness()` и `isCatalogStale()` — единые точки, где решается,
  свежа ли цена; страницы не вычисляют это самостоятельно.
- Истёкшие спецпредложения (`Offer.validUntil < сегодня`) не показываются как
  действующие: `diffOffers()` и страница программ отфильтровывают их.

## 4. Отсутствующие данные

Если официальный документ не раскрывает цену или характеристику, в интерфейсе
выводится **«Нет подтверждённых данных»**. Нельзя подставлять «типичное»
значение, среднее по рынку или значение соседней комплектации.

Практические следствия:

- `GWM POER KINGKONG` — официального прайс-листа нет, в каталоге одна запись
  типа `teaser` («от 3 099 000 ₽») с явной пометкой «требует подтверждения»;
- в `tco.ts` каждое слагаемое помечено `ValueSource`: `official` (из
  документа), `user` (ввёл пользователь) или `missing` (нет данных).
  Остаточная стоимость **не** оценивается «процентом от цены»: если её нет,
  она остаётся незаполненной и в расчёт не входит.

## 5. Разделение официального и расчётного

| Что | Как помечается |
| --- | --- |
| Данные из официального прайс-листа | ссылка на документ + дата действия |
| Условия официальной кредитной программы | карточка программы, ставка подписана как официальная |
| Предположение пользователя (ставка, срок, взнос, пробег, расход) | подпись **«Расчётное предположение»** |
| Результат математического расчёта | подпись «расчёт, а не оферта» |

Ни один результат не подаётся как предложение банка или дилера.

## 6. История цен

- `price-history.json` — точки **проверок**: что именно было на официальном
  источнике в конкретную дату.
- `price-changes.json` — 53 зафиксированные смены цен: было → стало, тип
  цены, дата, источник.
- История **не реконструируется из предположений**. Если цена не проверялась,
  точки нет.
- Стартовая точка (`seed:price-history`) — 2024-01-01, это отправная отметка
  для графика, а не «историческая цена, вычисленная backwards».

## 7. Как добавлять и менять цены

Только по официальному документу. Путь:

1. `npm run catalog:import` — пайплайн скачивает прайс-листы и разбирает их;
2. `npm run catalog:diff` — показывает расхождения с каталогом;
3. человек сверяет и вносит изменение в `src/data/haval/trims.ts` вручную;
4. `npm run catalog:report --apply` — дополняет журнал изменений.

Автоматическая перезапись каталога пайплайном **не производится**: неполный
или ошибочный разбор не должен портить подтверждённые данные. Подробнее —
[DATA_IMPORT.md](./DATA_IMPORT.md).
