# Тестирование

## 1. Быстрый прогон

```bash
npm test          # модульные тесты
npm run smoke     # рендер всех маршрутов без браузера
npm run typecheck # tsc -b --noEmit
npm run lint      # eslint
npm run build     # прод-сборка
npm run check     # всё перечисленное подряд
```

## 2. Как устроены модульные тесты

Логика написана на TypeScript, а запускает её встроенный раннер Node
(`node:test`). Схема:

```
scripts/test.mjs
  ├── esbuild собирает каждый tests/*.test.ts(x) в .tmp/tests/*.mjs (ESM)
  └── node --test запускает полученные бандлы
```

Вывод — ESM, потому что набор интерфейса поднимает jsdom **до** первого
импорта React (модули загружаются динамически), а `await import` на верхнем
уровне в CJS-выводе недопустим.

`.tmp/` не коммитится. Список наборов задаётся в `scripts/test.mjs`
(`SUITES`) — при добавлении нового файла его нужно добавить туда.

## 3. Наборы и что они покрывают

| Набор | Что проверяет |
| --- | --- | --- |
| `tests/unit.test.ts` | кредитная математика | аннуитет, обратные задачи (срок, сумма, ставка), остаток долга, досрочное погашение, ПДН, округление денег |
| `tests/calculators.test.ts` | калькуляторы | сценарий покупки, график, подбор по бюджету, обратный расчёт взноса, TCO, план накопления, трейд-ин |
| `tests/catalog.test.ts` | каталог | целостность данных: модели, комплектации, цены и их типы, официальные ТТХ, оснащение, предложения, наличие, история цен, свежесть |
| `tests/imports.test.ts` | импорт | валидация входных данных, дубликаты, отказ не затирает подтверждённые цены, поведение без ключей БД |
| `tests/import-pipeline.test.ts` | пайплайн импорта | разбор текста **реальных** официальных прайс-листов (M6, JOLION), отказ при неполном разборе, сопоставление с каталогом, diff |
| `tests/advisor.test.ts` | помощник | детерминированность, совпадение чисел с расчётами калькуляторов, честный отказ при отсутствии данных |
| `tests/ui.test.tsx` | интерфейс (jsdom) | восстановление избранного из `localStorage` после перемонтирования, синхронизация сравнения с `?trims=`, открытие и закрытие мобильного меню, ответы помощника на вопросы |

Всего **200 проверок**, 0 падений (прогон 2026-10-10).

## 4. Фикстуры

`tests/fixtures/price-list-m6.txt` и `tests/fixtures/price-list-jolion.txt` —
текст официальных прайс-листов, извлечённый из PDF на haval.ru. На них
проверяется не только разбор, но и совпадение цен каталога с официальными
документами.

## 5. Smoke-рендер

```bash
npm run smoke
```

`scripts/smoke.mjs` + `scripts/smoke-render.mjs` поднимают jsdom, монтируют
приложение в `MemoryRouter` и проходят по **всем** маршрутам, включая
страницы с параметрами (`/models/h9`, `/compare?trims=…`,
`/trims?drive=awd&…`, `/advisor?model=jolion&payment=35000`). Падение — любая
ошибка рендера или эффекта. Это замена SSR-проверки, которой на GitHub Pages
нет.

Роуты для обхода задаются в `scripts/smoke-render.mjs` — при добавлении
страницы добавьте и её.

## 6. Проверка данных (без сети)

```bash
node scripts/verify-parsed-documents.mjs
```

Сверяет каталог с сохранённым текстом официальных прайс-листов. Успех требует
пустых списков `changed` / `added` / `missing` / `ambiguous` и непустого
`unchanged`. Запускается в CI.

## 7. CI

`.github/workflows/ci.yml` на каждый push и PR:

1. guard: в отслеживаемых файлах нет секретных ключей Supabase;
2. Node 22, `npm ci`;
3. `npm run typecheck`;
4. `npm run lint`;
5. `npm test`;
6. `npm run smoke`;
7. `node scripts/verify-parsed-documents.mjs`;
8. `npm run seo` + проверка, что `public/sitemap.xml` не изменился (иначе —
   карта сайта устарела);
9. `npm run build`;
10. артефакт `dist` и проверка суммы JS-бандлов ≤ 3 MiB.

## 8. Как добавить тест

1. Создайте `tests/<область>.test.ts`.
2. Добавьте имя файла в `SUITES` в `scripts/test.mjs`.
3. Импортируйте код из `src/…` — тесты собираются из исходников, отдельная
   настройка путей не нужна.
4. Для модулей на JavaScript (например, `scripts/lib/*.mjs`) типы берутся из
   соседних `*.d.mts`-объявлений.
5. Запустите `npm test` и `npm run check`.

Соглашение: тест проверяет **поведение**, а не реализацию, и всегда содержит
проверку честного отказа — если данных нет, модуль должен вернуть ошибку или
«нет данных», а не подставить правдоподобное значение.

## 9. Чего тесты не покрывают

- реальную вёрстку и взаимодействие в браузере (нет e2e-прогона);
- соответствие графика платежей графикам конкретных банков (невозможно без
  доступа к их условиям);
- доступность haval.ru в момент запуска (сетевые проверки вынесены в
  отдельный workflow `prices.yml`).
